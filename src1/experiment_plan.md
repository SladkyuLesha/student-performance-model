# План экспериментов

## Задача и данные

Цель — предсказать итоговую оценку `G3` как числовое значение; это задача регрессии. Основной источник для текущих экспериментов — `data/initial/initial.csv` (237 строк), полученный из открытого исходного набора. Порции `data/incoming/batch_01.csv`–`batch_04.csv` оставлены для последующей проверки и не используются для выбора моделей и параметров.

Сравниваются два сценария на одних и тех же строках:

- Ранний: без `G1`, `G2` и целевой `G3` во входе.
- Поздний: с `G1` и `G2`, но без целевой `G3` во входе.

Для каждого признака необходимо проверить его фактическую доступность в момент прогноза. Например, число пропусков `absences` может быть известно не полностью на раннем этапе обучения.

## Метрики и базовое решение

- Основная метрика выбора — средняя MAE по блокам кросс-валидации: чем меньше, тем лучше. Среди результатов в пределах 0,05 балла от минимума выбирается более простой кандидат по фиксированному порядку в `src1/run_experiments.py`. Стандартное отклонение метрики по блокам показывается отдельно и не является доверительным интервалом.
- Дополнительные метрики — RMSE и R²; их также рассматриваем по блокам, а не по тестовой выборке при выборе модели.
- Базовое решение — `DummyRegressor(strategy="median")`: предсказывает медиану обучающих значений и сравнивается с остальными по MAE.

## Разбиение и валидация

1. Сначала 20 % строк откладываются в test. Оставшиеся 80 % делятся на train и validation в соотношении 80:20. На каждом разбиении используется `random_state=42`; для обоих сценариев применяются одни и те же позиции строк.
2. Внутри train модели сравниваются пятиблочной кросс-валидацией `KFold(n_splits=5, shuffle=True, random_state=42)`. Указываются среднее и разброс метрик по блокам. Каждый блок по очереди становится внутренней validation-частью, остальные четыре — обучающей.
3. Внешняя validation-часть используется для однократной проверки кандидата, выбранного по CV. Повторная настройка по ней может привести к подгонке под validation, поэтому её результаты не являются независимой финальной оценкой.
4. `test` не используется для настройки признаков, параметров или выбора модели; он предназначен для последующей итоговой оценки. Новые порции также не используются в подборе.
5. Параметры предобработки и новых признаков оцениваются только по обучающей части каждого блока кросс-валидации. Подготовка и модель объединены в `Pipeline` и `ColumnTransformer`. Ранняя остановка бустинга отключена; каждый кандидат использует 200 итераций.
6. Скрипт `python -m src1.split_data` сохраняет позиции строк разбиения и SHA-256 исходного файла в `reports/tables/model_split.json`. Контрольная сумма позволяет обнаружить изменение файла; позиции отсчитываются с нуля. При изменении данных нужно явно пересмотреть и заново сформировать протокол, а не молча использовать старые позиции.

## Ограничения

Разбиение по строкам не доказывает независимость реальных студентов: идентификатора студента и дат поступления нет. Точные совпадения профилей без `G1`, `G2`, `G3` между исходной частью и порциями не обнаружены; внутри исходной части они также отсутствуют. При изменении данных проверку нужно повторить. Признаки, которые появятся только после момента прогноза, использовать нельзя.

EDA выполнялся до создания отложенной test-выборки, поэтому она не является полностью независимой от всей предыдущей исследовательской работы. Исходный набор мал, и оценки могут заметно зависеть от разбиения. Четыре порции образованы случайно и не являются реальными будущими временными периодами.

Ранее полученные результаты моделей на расширенном синтетическом наборе — отдельные предварительные эксперименты. Синтетические записи не заменяют новых реальных студентов; выводы о качестве на реальных данных требуют проверки на реальных отложенных наблюдениях.
