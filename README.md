# Student Performance Prediction

Проект по анализу табличных данных о студентах и построению модели машинного обучения для предсказания итоговой оценки `G3`.

Цель проекта - собрать понятный и воспроизводимый ML-пайплайн: загрузка данных, первичный анализ, preprocessing, разбиение данных, обучение моделей, расчет метрик, построение графиков и сохранение результатов в `reports`.

Помимо обучения моделей, проект включает подготовку последовательных порций данных, расширенный разведочный анализ (EDA), проверку статистических гипотез и проектирование архитектуры обработки новых наблюдений.

В проекте используются два CSV-файла:

- `student_data_500k.csv` - расширенный датасет на 500000 строк.

Базовый файл `student_data.csv` используется для воспроизводимого разбиения и EDA. Небольшой исходный набор и созданные порции могут храниться в Git; большой `student_data_500k.csv` остаётся локальным и не требуется для запуска аналитического ноутбука.

Расширенный датасет содержит технический столбец `record_id`. Он исключается из признаков, потому что является идентификатором записи, а не характеристикой студента.

### Разбиение базового набора

Для моделирования последовательного поступления новых наблюдений базовый набор из 395 записей перемешивается с `random_state=42` и делится на:

- `data/initial/initial.csv` — 237 записей (60%);
- `data/incoming/batch_01.csv` — 40 записей;
- `data/incoming/batch_02.csv` — 40 записей;
- `data/incoming/batch_03.csv` — 39 записей;
- `data/incoming/batch_04.csv` — 39 записей.

Все 395 записей распределяются между частями без повторного выбора одной и той же позиции. Порции имитируют новые выгрузки, а не фактическое поступление новых студентов.

## Целевая Переменная

Целевая переменная:

```text
G3
```

`G3` - итоговая оценка студента. Задача проекта формулируется как регрессия: модель предсказывает числовое значение итоговой успеваемости.

В проекте сравниваются два сценария:

- с `G1` и `G2` - модель использует промежуточные оценки;
- без `G1` и `G2` - модель прогнозирует `G3` только по остальным признакам.

## Предыдущий Pipeline

Этот вариант относится к прежнему эксперименту на расширенных данных. Категории кодируются до разбиения, а два сценария разбиваются отдельно, поэтому его результаты не следует считать окончательной независимой оценкой.

1. `load_data` загружает CSV-файл в `pandas.DataFrame`.
2. `preprocess_data` удаляет `record_id` и кодирует категориальные признаки через `pd.get_dummies`.
3. `make_feature_sets` создает два набора признаков: с `G1/G2` и без `G1/G2`.
4. `honest_split_data` группирует идентичные профили признаков и выполняет разбиение через `GroupShuffleSplit`; это не доказывает независимость студентов и не устраняет все возможные утечки.
5. `train_models.py` обучает `DummyRegressor`, `LinearRegression` и `HistGradientBoostingRegressor`.
6. `metrics.py` рассчитывает `MAE`, `MSE`, `RMSE` и `R2`, а затем собирает строки для итоговой таблицы.
7. `visualization.py` строит графики сравнения моделей и факт/прогноз.
8. `run_training.py` запускает весь текущий пайплайн и сохраняет результаты.

## Модели

### DummyRegressor

Baseline-модель:

```python
DummyRegressor(strategy="mean")
```

Она всегда предсказывает среднее значение `G3`. В новом эксперименте используется `strategy="median"`: он предсказывает медиану обучающей части и служит точкой отсчёта по MAE.

### LinearRegression

Линейная регрессия используется как простая интерпретируемая модель для сравнения с baseline и бустингом.

### HistGradientBoostingRegressor

В предыдущем эксперименте применялся градиентный бустинг из scikit-learn. В новом эксперименте он сравнивается с другими моделями; выбор не фиксируется заранее.

Текущие параметры последнего запуска:

```text
max_iter=20000
learning_rate=0.03
min_samples_leaf=70
l2_regularization=2.0
n_iter_no_change=60
random_state=42
```

## Метрики

### MAE

```text
MAE = mean(abs(y_true - y_pred))
```

Средняя абсолютная ошибка. Показывает, на сколько баллов в среднем ошибается модель.

### MSE

```text
MSE = mean((y_true - y_pred)^2)
```

Средняя квадратичная ошибка. Сильнее штрафует большие ошибки.

### RMSE

```text
RMSE = sqrt(MSE)
```

Корень из MSE. Измеряется в тех же единицах, что и `G3`.

### R2

```text
R2 = 1 - sum((y_true - y_pred)^2) / sum((y_true - mean(y_true))^2)
```

Показывает, какую долю разброса целевой переменной объясняет модель. Например, `R2 = 0.90` означает, что модель объясняет около 90% вариативности `G3` на выбранной проверочной выборке.

## Результаты

### Сравнение на начальной части исходных данных

На 151 обучающей строке выполнена пятиблочная кросс-валидация; validation содержит 38 строк. Перебрано 33 варианта для каждого сценария. Из моделей в пределах 0,05 балла MAE от лучшего CV-результата выбирается более простая по заранее заданному порядку. Значения validation ниже получены **до** повторного обучения выбранной модели на train и validation вместе.

| Сценарий | Выбрано по CV | MAE CV (среднее ± стандартное отклонение) | MAE validation | RMSE validation | R² validation |
| --- | --- | ---: | ---: | ---: | ---: |
| Без G1/G2 | Lasso, alpha=1.0 | 3,030 ± 0,451 | 3,817 | 4,620 | -0,017 |
| С G1/G2 | Random Forest | 0,862 ± 0,109 | 1,238 | 1,926 | 0,823 |

В позднем сценарии лучшую среднюю MAE CV получил градиентный бустинг: 0,845. Случайный лес выбран по правилу допуска 0,05 как более простой вариант из заранее заданного списка; это не означает статистически подтверждённого преимущества. На небольшом validation ранний сценарий показал отрицательный R². Данные исследовались ранее; итоговые 48 строк test затем оценены отдельно.

На test ранняя Lasso получила MAE 3,721 против 3,750 у baseline и не прошла заранее заданные пороги. Поздний Random Forest получил MAE 1,425, бустинг — 1,586; оба прошли численные пороги. Эти результаты относятся к небольшому набору и не доказывают качество на других популяциях. Подробности, ограничения и предварительные решения приведены в `models/model_cards.md`.

Таблицы по кандидатам, блокам CV, коэффициентам и validation находятся в `reports/tables/model_comparison/experiments/`. Графики регуляризации, глубины дерева и сравнения новых признаков находятся в `reports/figures/model_comparison/experiments/`. Сохранённые `models/early_model.joblib` и `models/late_model.joblib` обучены повторно на train и validation вместе; поэтому validation-метрики выше не являются оценкой этих повторно обученных моделей.

## Воспроизводимость

- Все случайные разбиения и модели используют `random_state=42`, где это применимо.
- Исходный CSV не изменяется при подготовке порций; небольшой базовый набор и порции можно версионировать в Git, расширенный файл на 500000 строк хранится локально.
- Метрики и выводы добавляются только после реального запуска кода.
- Для расширенного датасета используется групповое разбиение через `GroupShuffleSplit`.
- Порции создаются детерминированно отдельным скриптом, а EDA выполняется по исходной части данных.
- Результаты анализа, архитектурные схемы и таблицы сохраняются отдельно от артефактов обучения моделей.
- Новый процесс обучает обработку признаков только внутри соответствующей обучающей части CV и записывает версии библиотек с сохранёнными моделями. Фиксированные минимальные версии в `requirements.txt` не гарантируют полностью одинакового окружения на другой машине.
- Файлы моделей `joblib` следует загружать только из доверенного источника: этот формат может выполнять код при загрузке.
