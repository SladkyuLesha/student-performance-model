# Student Performance Prediction

Проект по анализу табличных данных о студентах и построению модели машинного обучения для предсказания итоговой успеваемости (`G3`).

Цель проекта - постепенно построить понятный и воспроизводимый ML-пайплайн: от загрузки данных и первичного анализа до baseline-модели, градиентного бустинга, оценки качества, анализа ошибок и сохранения результатов.

## Данные

В проекте используются два CSV-файла:

- `student_data.csv` - базовый датасет на 395 строк.
- `student_data_500k.csv` - расширенный датасет на 500000 строк.

Источник базового датасета: [Student Performance Data на Kaggle](https://www.kaggle.com/datasets/devansodariya/student-performance-data).

Файлы данных должны находиться локально в `data/raw`. CSV-файлы не добавляются в Git, чтобы не хранить большие данные в репозитории.

Расширенный датасет содержит технический столбец `record_id`. Он исключается из признаков, потому что является идентификатором записи, а не характеристикой студента.

## Целевая Переменная

Целевая переменная:

```text
G3
```

`G3` - итоговая оценка студента. Задача проекта формулируется как регрессия: модель предсказывает числовое значение итоговой успеваемости.

В проекте отдельно сравниваются два сценария:

- с `G1` и `G2` - модель использует промежуточные оценки;
- без `G1` и `G2` - модель пытается прогнозировать итоговую оценку только по остальным признакам.

Это важно, потому что `G1` и `G2` очень сильно связаны с `G3`, но в реальной задаче они могут быть недоступны заранее или делать прогноз слишком очевидным.

## Модели

### DummyRegressor

Baseline-модель:

```python
DummyRegressor(strategy="mean")
```

Она предсказывает среднее значение `G3`. Нужна как точка отсчета: любая полезная модель должна быть лучше простого среднего.

### LinearRegression

Простая линейная модель для первичного сравнения. Она помогает понять, насколько много можно объяснить линейными зависимостями.

### HistGradientBoostingRegressor

Основная нелинейная модель проекта. Используется histogram-based gradient boosting из scikit-learn, потому что он подходит для больших табличных данных.

Основные параметры в длинном эксперименте:

```text
learning_rate=0.005
max_iter=50000
max_leaf_nodes=31
min_samples_leaf=50
l2_regularization=1.0
early_stopping=True
validation_fraction=0.1
n_iter_no_change=30
random_state=42
```

Для быстрой честной проверки перед переносом модели в `src` использовался сокращенный запуск:

```text
max_iter=10000
early_stopping=True
random_state=42
```

## Метрики

Используемые метрики:

### MAE

```text
MAE = mean(abs(y_true - y_pred))
```

Средняя абсолютная ошибка. Показывает, на сколько баллов в среднем ошибается модель.

### MSE

```text
MSE = mean((y_true - y_pred)^2)
```

Средняя квадратичная ошибка. Сильнее штрафует большие ошибки.

### RMSE

```text
RMSE = sqrt(MSE)
```

Корень из MSE. Измеряется в тех же единицах, что и `G3`.

### R2

```text
R2 = 1 - sum((y_true - y_pred)^2) / sum((y_true - mean(y_true))^2)
```

Показывает, какую долю разброса целевой переменной объясняет модель. Например, `R2 = 0.90` означает, что модель объясняет около 90% вариативности целевой переменной на выбранной проверочной выборке.

## Проверка Надежности Split

На расширенном датасете были найдены повторы:

| Проверка | Результат |
| --- | ---: |
| Полные дубликаты без `record_id` | 190064 |
| Доля полных дубликатов без `record_id` | 38.0128% |
| Дубликаты по признакам без `G3` | 274245 |
| Доля дубликатов по признакам без `G3` | 54.8490% |
| Test-строки, признаки которых уже были в train при random split | 63203 |
| Доля таких test-строк | 63.2030% |

Обычный random split оказался слишком оптимистичным: одинаковые строки признаков могли попадать одновременно в train и test.

Для более честной оценки добавлен `GroupShuffleSplit`:

| Split | Пересечения train/test | Доля пересечений | Train | Test |
| --- | ---: | ---: | ---: | ---: |
| По признакам с `G1/G2` | 0 | 0.0000% | 400013 | 99987 |
| Strict split без `G1/G2/G3` | 0 | 0.0000% | 400751 | 99249 |

`Strict GroupShuffleSplit` - это не отдельный класс scikit-learn, а наше название для более строгого варианта `GroupShuffleSplit`: группы строятся по признакам без `G1`, `G2` и `G3`.

## Результаты На Честных Split

После проверки дубликатов модели были повторно проверены на честных split:

| Модель | Признаки | Метод оценки | MAE | MSE | RMSE | R2 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| LinearRegression | с `G1/G2` | GroupShuffleSplit | 1.167 | 2.253 | 1.501 | 0.846 |
| LinearRegression | без `G1/G2` | Strict GroupShuffleSplit | 2.604 | 10.730 | 3.276 | 0.249 |
| HistGradientBoostingRegressor | с `G1/G2` | GroupShuffleSplit, `max_iter=10000` | 0.843 | 1.120 | 1.059 | 0.924 |
| HistGradientBoostingRegressor | без `G1/G2` | Strict GroupShuffleSplit, `max_iter=10000` | 0.925 | 1.359 | 1.166 | 0.905 |

Вывод: качество бустинга на честном split снизилось слабо. Сценарий с `G1/G2` почти не изменился. Сценарий без `G1/G2` ухудшился заметнее, но все еще остается сильным: `R2 = 0.905`, `MAE = 0.925`.

Это значит, что хороший результат бустинга не объясняется только пересечениями одинаковых строк. Но для финального проекта лучше использовать честную схему разбиения через `GroupShuffleSplit`.

## Текущий Вывод

1. `G1` и `G2` являются самыми сильными предикторами итоговой оценки `G3`.
2. `LinearRegression` хорошо работает при наличии `G1/G2`, но слабо объясняет `G3` без них.
3. `HistGradientBoostingRegressor` значительно лучше работает с нелинейными зависимостями.
4. Даже без `G1/G2` бустинг показывает сильное качество на честном split.
5. Расширенный датасет содержит много повторов, поэтому финальная оценка должна использовать честное групповое разбиение.
