# Правила работы над проектом

Этот проект посвящен построению модели машинного обучения для анализа и предсказания итоговой успеваемости студентов на основе табличных данных.

## Общий подход

- Работать постепенно: сначала план, затем небольшой фрагмент, затем объяснение и проверка.
- Не делать проект целиком за один шаг.
- Не менять много файлов одновременно без необходимости.
- Перед изменениями перечислять, какие файлы будут созданы или изменены и зачем.
- Сначала делать простое рабочее решение, затем улучшать его.
- Не удалять существующий код или данные без объяснения причины.

## Данные

- Исходные данные хранить в `data/raw`.
- Обработанные данные хранить в `data/processed`.
- Не изменять исходные CSV-файлы напрямую.
- Следить, чтобы preprocessing не приводил к data leakage.
- Все разбиения данных делать воспроизводимыми с `random_state=42`, где это применимо.

## Код

- Основной код хранить в `src`.
- Исследовательские ноутбуки хранить в `notebooks`.
- Писать понятный код без лишнего усложнения.
- Комментарии добавлять только там, где они помогают понять логику.
- Не добавлять сложные библиотеки без необходимости.
- Предлагать код небольшими блоками и объяснять, что делает каждый блок.

## Моделирование

- Сначала строить baseline-модель.
- Затем добавлять основную модель градиентного бустинга.
- Оценивать качество через RMSE, MAE и R2.
- Не выдумывать метрики, выводы и результаты: использовать только то, что реально получено из кода.
- Анализировать важность признаков и ошибки модели после обучения.

## Отчеты

- Графики сохранять в `reports/figures`.
- Таблицы с результатами сохранять в `reports/tables`.
- README обновлять постепенно, по мере появления рабочих частей проекта.

## README policy

- После каждого крупного этапа проекта README.md нужно проверять и при необходимости обновлять.
- README.md должен оставаться аккуратным, структурированным и понятным для человека, который впервые открывает проект.
- В README.md нельзя выдумывать метрики, графики, выводы или результаты модели.
- Если часть проекта еще не реализована, ее нужно описывать как план, TODO или будущий этап.
- Перед обновлением README.md нужно кратко объяснять, какие разделы будут добавлены или изменены.
- README.md должен обновляться постепенно, по мере появления реального кода, данных, графиков, метрик и выводов.

## Общение

- Объяснения писать на русском языке.
- Если пользователь присылает ошибку, сначала объяснить причину простыми словами, затем предложить минимальное исправление.
- Если пользователь пишет код сам, проверять конкретные места с ошибками или возможными улучшениями.
- Перед ответом по работе в ноутбуке проверять сохраненные output-ячейки `.ipynb`, если ноутбук доступен и это помогает оценить результат без пересказа пользователя.
- После каждого крупного шага предлагать Git commit с понятным названием.
